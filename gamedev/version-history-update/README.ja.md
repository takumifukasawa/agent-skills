# version-history-update

プロジェクトのバージョン別変更履歴（changelog）ドキュメントを、リポジトリ内に散らばった版の情報源（AB テスト定義、設定 variant のメモ、分析の結論、配信ロールアウト表、release コミット）から抽出し直して、既存の記述を壊さずに差分でマージ更新するスキルです。

> このファイルは人間向けの説明です。Claude が実際に読むのは [SKILL.md](./SKILL.md) で、動作はそちらで決まります。

## こんなときに使う
- 「バージョン履歴を更新」「VersionHistory を更新して」
- 「changelog に新 version を追加」「この版でやったことを履歴に追記」
- 新しい版を出した / 実験を締めた後に履歴 doc に反映したいとき
- 履歴 doc がまだ無く、散らばった情報から初版を組みたいとき（初回はフル生成、以降は差分マージ）
- 特に AB テストやフィーチャーフラグの variant を回しながらリリースするプロダクト（ハイパーカジュアルなど）で、各版の「やったこと + 結果（勝ち / null / ドロップ）」を 1 か所にまとめておくのに向く

## やること
1. **履歴 doc と情報源を探す** — 対象の doc（`VersionHistory.md`、`CHANGELOG.md` など）を探し、無ければ作る場所を確認する。情報源は実験定義・variant の記述・分析の結論・ロールアウト表・`git log` の release コミット・既存メモなど、種類を手がかりにプロジェクトごとに毎回探す
2. **差分を特定する** — 既存 doc で記録済みの最新版を把握し、それより新しい版や内容が変わった版だけを抽出する
3. **非破壊マージ**
   - タイムライン表に行を足す（版 → 配信日 → 主な変更 → 結果）
   - 新しい版の詳細セクションを足す。結果が出ていなければ `WIP / 測定前` と書く
   - 「現在の live 状態」（有効なフラグ・現行アームなど）を最新にする
   - 古い版の記述や人が整えた文章は残す
   - 各主張に出典パスを併記し、情報源どうしが食い違うときにどれを正とするかを注記する
   - 見つけたデータの不整合や罠は「Notes / 既知の罠」に、どこで事故るかまで書く
4. **整合確認** — 版と配信日をロールアウト表と、アームの増減をテスト定義と突き合わせる。variant の記述をいくつか実ファイルと照合し、索引 doc からのリンクを足す

## 推奨する doc 構成
既存の構成があればそれに合わせる。無ければ次の順。
1. タイムライン表（1 版 1 行）
2. 最近の版の詳細
3. 実験軸のサマリ
4. 古い版の系譜
5. 付録: 全 variant 表
6. Notes / 既知の罠

## 注意点
- コードやアセットは変更しない（履歴 doc の記述だけ）
- 結果が出ていない版に推測の結論を書かない
- フル再生成で人手の記述を上書きしない
- SKILL.md 末尾の例（AB テストを回しているモバイルゲーム）は、手順の当てはめ方の参考として読む
