# game-store-assets

Google Play のストア掲載素材一式を作るスキルです。実際に動いているゲームを headless Chromium でキャプチャしたスマホ / タブレット用スクリーンショット、1024x500 のフィーチャーグラフィック、そして掲載テキスト（簡単な説明 / 詳しい説明）を用意します。

> このファイルは人間向けの説明です。Claude が実際に読むのは [SKILL.md](./SKILL.md)（英語）で、動作はそちらで決まります。

## こんなときに使う
- 「ストア画像を作って」「スクショ一式」「フィーチャーグラフィック」
- 「簡単な説明 / 詳しい説明を書いて」「Play Console の説明文」
- 選ぶ候補としてゲームプレイのスクショを大量に撮りたいとき
- 正方形のアプリアイコンは兄弟スキル `game-icon-from-screenshot` の担当。手描きのプロモアートには使いません

## やること
1. **スクショ** — `scripts/screenshots.cjs` で、ストアの正確なサイズでまとめて撮る。モードは 3 つ
   - `shots`: ポーズを付けた静止ショット（準備画面・リザルト画面など）
   - `live`: `keepAlive` で自動操作しながら、`pick` が良いと判断したフレームを撮る
   - `timed`: 自動プレイ（`?autoplay=` やデモモード）があるゲームを一定間隔で撮る
2. **候補から選んでもらう** — ステージごと・進み具合（序盤 / 中盤 / 終盤）ごとに多めに撮り、約 15 枚に絞る。自分の確認は `scripts/contact_sheet.py` の番号付き一覧で。ユーザーには **選定ページ（Artifact）** で選んでもらう（Artifact が使えない環境では一覧画像を送って番号で答えてもらう）。推薦は理由付きで
3. **選定ページ** — `scripts/build_picker.py <spec.json> <out.html>` で組み立て、Artifact（`capabilities: {"db": {}}`）で公開する
   - 画像グループ: スクショは複数選択（選んだ順＝アップロード順、← → で並べ替え）、フィーチャーグラフィックと **アプリアイコン** は 1 つ選択。撮り直しは同じ `pick` キーの別グループとして足す
   - 説明文グループ: 案ごとに提出用の本文・日本語訳・字数と、右上の「コピー」ボタン
   - 各グループのコメント欄（Claude への指示）と「全体への指示」
   - 選択は Artifact の db `picks/current` に保存され、Claude が `ArtifactData` で読む。ユーザーが「保存しました」と言ったら読み、コメントに対応する
   - アイコンだけの選定にも、ストア画像と一緒の選定にも使える（アイコン候補は `game-icon-from-screenshot` で作る）
4. 決まったものをアップロード順（`1-…png`, `2-…`）で 1 フォルダにまとめ、何をどう撮ったか・落選案をプロジェクトの docs に記録する
5. **フィーチャーグラフィック** — HUD を消したゲーム画面を全面に使う（`screenshots.cjs` を横長 `target` で）か、`scripts/feature_graphic.py` でスクショ + タイトル + タグラインを合成するか、どちらにするか確認する。雰囲気重視のゲームは全面が既定
6. **掲載テキスト** — `references/listing-text.md` に沿って書く。抽象的に（ステージの数や種類・進行のルールなど、変わりうる仕様の細部は書かない）。提出は英語、日本語訳を添える

## 前提・必要なもの
- ゲームがローカル URL で動いていること
- Playwright + Chromium（自動で探す。無ければ `npx playwright install chromium`）
- Pillow（Python）
- フィーチャーグラフィックのタイトル用 `.ttf` フォント（可変フォントも可）

## 注意点
- アンチエイリアスは viewport を大きくせず `superSample` で稼ぐ。巨大な canvas は headless の描画 / 物理ループを止めることがある。viewport は実際に遊ぶサイズ（例: 1080x1920）のままにする
- headless の WebGL には `--use-angle=swiftshader --enable-unsafe-swiftshader` が必要（無いと真っ黒）。遅いのでページは 1 枚ずつ開く
- bloom / postFX のあるゲームでは `live` の物理が止まり、被写体が出現位置で固まることがある。被写体の `y` が変化するか先に確かめ、止まっていれば `scripts/pose-capture.cjs` で手動アニメーションさせる（ベジェ曲線の軌道 + `t*t` のイーズイン、パーティクルの増量は控えめに）
- CSS で HUD を隠すとき、canvas の親まで隠さない。同じ小さなファイルが並んだら何も描画されていない
- 縦専用ゲームで横長バナーを撮るときは、アスペクト上限を `routes`（キャプチャ時だけのソース差し替え）で外す。ゲームのファイル自体は触らない
- 9:16 の 1080x1920 一式でスマホ・7 インチ・10 インチタブレットをまかなえる。フォームの例示サイズに合わせて小さいサイズを別に作らない
- ゲームの雰囲気は手描きでなく実際のスクショで表す。一時的に強めたエフェクトは控えめに
- PIL で半透明の要素を合成するときは透明レイヤー + `alpha_composite` を使う
- 生成画像は、プロジェクトが既にストア素材を管理していない限り git に入れない
- 縦画面ゲームのフィーチャーグラフィックは、プレイ画面を横に広げて撮るより、縦のプレイから被写体のまわりを 1024:500 の帯で切り抜くほうが被写体が大きく見える
- 「被写体を中央に」は、Node 側で位置を確かめてから撮ると、スクショ（software GL で遅い）までに被写体が動いてずれる。ページ内で毎フレーム待ち、中央に来た瞬間にシーンを一時停止して撮る

## 同梱ファイル
- `scripts/screenshots.cjs` — スクショのハーネス（静止 / live / timed、supersample、正確なサイズへのリサイズ）
- `scripts/pose-capture.cjs` — 物理が止まるゲーム用の決定的なポーズアニメーション撮影
- `scripts/feature_graphic.py` — スクショ + タイトル + タグラインでフィーチャーグラフィックを合成
- `scripts/contact_sheet.py` — 候補画像を番号付きで 1 枚に並べる
- `scripts/build_picker.py` と `scripts/picker/picker.template.html` — 選定ページ（Artifact）を JSON の設定から組み立てる
- `scripts/resize.py` — 画像を指定アスペクトで切り抜いて WxH ちょうどにリサイズ
- `references/play-store-sizes.md` — Play ストアの画像サイズ要件とプリセット
- `references/listing-text.md` — 掲載テキストの文字数制限・書き方・関連フォーム項目
