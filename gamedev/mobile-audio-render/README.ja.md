# mobile-audio-render

実機（特に Android Chrome）で起きる Web Audio のぶつぶつ・プチッという音・音割れ・途切れ・音量不足と、それを巻き込む重い描画（three.js の解像度、antialias、ポストプロセス）を突き止めて直すスキルです。推測で設定を試すのではなく、USB でつないだスマホのオーディオスレッドを記録して、締め切りに間に合わなかった回数を数えます。

> このファイルは人間向けの説明です。Claude が実際に読むのは [SKILL.md](./SKILL.md)（英語）で、動作はそちらで決まります。

## こんなときに使う
- 「音がぶつぶつする」「たまにブツっとなる」「ぷちっと鳴る」
- 「音が割れる」「ビリつく」「音が途切れる」「音が小さい」
- 「Android だけ音がおかしい」
- 「低スペック端末で重い」「かくつく」「解像度を下げたい」「antialias どうする」
- Web Audio のコードを書くときや、低スペック端末向けに three.js のレンダラを設定するときのレビュー用チェックリストとしても使う

## やること
1. **症状の種類を見分ける** — 不規則で遊ぶほど増えるぶつぶつはアンダーラン（オーディオスレッドの締め切り落ち）、決まった瞬間のプチッは音作りの問題、音量を上げたときだけ低音がビリつくのはミックス全体が小さすぎ、描画がかくつくと音も一緒に崩れるのは描画が重すぎ
2. **アンダーランならまずコードを確認**（可能性の高い順）
   - 鳴り終わったノートの `GainNode` などが接続されたまま（`ended` で `disconnect()` する。これが一番効いた）
   - `latencyHint` を `"balanced"` にする（`"playback"` が常に良いとは限らない）
   - 毎フレーム同じ値のオートメーションを送っている
   - 同じ瞬間に大量のノートを鳴らしている
   - 鳴らない回路（ゲイン 0 のノイズやリバーブ）を作っている
   - 描画が重い（描画オフのスイッチを作って比較）
3. **それでも分からなければ実機で記録** — adb でポートを転送し、`scripts/trace.mjs` で記録、`scripts/analyze.py` で集計。毎秒の取りこぼし数・render の所要時間・実際のバッファサイズを読む。条件は URL クエリで切り替えてリビルドなしで A/B する
4. **音作りの問題なら** — 立ち上がり / 終わりのランプ、`cancelAndHoldAtTime` の使用、コンプレッサーの attack、キックのリバーブ送り、ハイハットの attack、全体のラウドネス（約 -15 LUFS、ピーク -1 dBFS 未満）を確認する
5. **描画が重いなら（three.js）** — ポストプロセスがあれば canvas の `antialias: false`、pixel ratio を 1.5 程度に制限、MSAA の `samples` と bloom 解像度をクエリで下げられるように、`preserveDrawingBuffer: true` にしない。目視でなく計測で判断する
6. **直したら** — 端末・条件・修正前後の数値をプロジェクトの docs に残す

## 前提・必要なもの
- Web Audio API を使う Web ゲーム（エンジンは問わない）
- 実機トレースには、USB デバッグを有効にした Android 端末、adb（`brew install android-platform-tools`）、Node 22 以上、python3
- ラウドネス確認には ffmpeg

## 注意点
- 推測した設定の URL をユーザーに何度も試させない。往復ばかり増えて外れが多かった
- 充電専用ケーブルだと Mac から端末が見えない
- スマホは熱くなると遅くなる。計測の間は約 45 秒空け、順番を入れ替えて確認する
- `disabled-by-default-webaudio.audionode` は付けない（それ自体でぶつぶつが起きるほど重い）
- `adb shell input tap` は使わない（前面にある別のアプリを押してしまう）。`trace.mjs` は CDP 経由でページをタップする
- 端末やブラウザのせいかを切り分けるときは、`scripts/audio-test.html` を実機で開く。音を切り替えるときはフェードしないと切り替え自体がクリック音になる

## 同梱ファイル
- `scripts/trace.mjs` — Android 端末の Chrome でオーディオスレッドのトレースを記録する
- `scripts/analyze.py` — トレースを集計する（render 時間、取りこぼし、毎秒の推移、バッファサイズ）
- `scripts/audio-test.html` — 描画なし・音だけのテストページ
- `references/webaudio-crackle.md` — Android Chrome での Web Audio のぶつぶつに関する事実と実測値、アンダーランではないプチッという音
- `references/render-cost.md` — 低スペック端末での three.js の描画コストと、実機で比較するためのスイッチ
