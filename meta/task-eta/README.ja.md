# task-eta

バックグラウンドで動いている Claude Code のタスク（`run_in_background` の Bash や、バックグラウンド起動の Agent）について、処理を止めずに進捗を覗き、残り時間を見積もるスキルです。

> このファイルは人間向けの説明です。Claude が実際に読むのは [SKILL.md](./SKILL.md)（英語）で、動作はそちらで決まります。

## こんなときに使う
- 「あとどれくらいで終わる?」「進捗どう?」「終わりそう?」
- 「あの裏で動いてるやつ、あとどれくらい？」
- 「how much longer」「is it done yet」

## やること
1. **task_id を探す**: バックグラウンドの Bash / Agent を起動したときのツール結果に返っています。会話をさかのぼって探します。動作中の全タスクを列挙するツールはないので、compaction などで本当に失われていたら、捏造せずにユーザーに再共有かやり直しを頼みます。
2. **ブロックせずに覗く**: `TaskOutput` を `block: false` と短い `timeout`（例: `1000`）で呼びます。Bash や `remote_agent` のタスクなら、起動時に返った出力ファイルを `Read` するほうが安く済みます。`local_agent` のタスクは `.output` ファイルを `Read` せず、`TaskOutput` の結果を使います（サブエージェントの全トランスクリプトへの symlink で、context があふれるため）。
3. **進捗シグナルから見積もる**（信頼度の高い順）:
   - 明示的な進捗表示（「step 4/12」「45%」「1200/5000 rows」）→ 経過時間 ÷ 進捗 × 残り
   - ログの出る間隔（1 件ごとに 1 行など）と、分かっている総数
   - 同じセッションで同じコマンドを流したときの所要時間
   - どれもなければ数字を作らず、「進捗シグナルなし、N 分経過、最後の行は X」と正直に答えます
4. **報告する**: 経過時間、見積もり（または「不明」とその理由）、根拠にしたシグナルを伝えます。またすぐ聞かれそうなら、手動で何度も確認する代わりに `Monitor` を提案します。

## 注意点
- 「タスク」は 2 種類あります。このスキルが扱うのはバックグラウンドプロセスのほうです。`TaskCreate` / `TaskList` / `TaskGet` / `TaskUpdate` は作業整理用の TODO ボードで、実行中プロセスの進捗は分からないので使いません。
- `TaskOutput` を `block: true`（デフォルト）で呼ぶと、タスクが終わるまで待たされます。
- 根拠のない数字で ETA を答えません。
- `sleep` と再確認を繰り返す自前のポーリングループは書かず、`Monitor` を使います。
