# context-catchup

新しいセッションの冒頭に、プロジェクトの docs・assistant memory・VCS の状態から「現在地（何が済み / 何が途中 / 次の一手）」を少ないトークンで読み込み、ブリーフィングとしてまとめるスキルです。

> このファイルは人間向けの説明です。Claude が実際に読むのは [SKILL.md](./SKILL.md)（英語）で、動作はそちらで決まります。

agent-harness を導入していないリポジトリ向けです。導入済み（`.harness/` と `docs/handoff.md` がある）なら、同じ役割でより安く読める `session-catchup` を使います。書き込み側は [context-handoff](../context-handoff/README.ja.md) です。

## こんなときに使う
- 「docs やメモリを読んでコンテクストを理解して」「背景を把握して」
- 「現状/現在地を教えて」「前回の続きから」「キャッチアップして」
- 「引き継ぎ(ハンドオフ)を読んで」「この repo の状況を掴んで」
- 長く中断した後の再開、並行タスクが複数あって何から手を付けるか決めたいとき

単発の質問や、このセッションですでに文脈を積んでいるとき、特定ファイルの実装中には使いません。

## やること
1. **素材の在り処を一覧する**: `ls -la` と指示ファイル（`CLAUDE.md` / `AGENTS.md` / `README.md`）を手がかりに、docs・memory（Claude Code なら `~/.claude/projects/<path-slug>/memory/`）・VCS・成果物の候補を作ります。この時点では中身を読まず、mtime の新しいものを優先します。
2. **索引を並列で読む**: memory の `MEMORY.md`、バックログや changelog などの横断 doc、handoff / WIP と名の付く doc を最優先で読みます。memory 本体は関係するものだけ読みます。
3. **resume point を特定する**: handoff の「次にやる」節、memory の残タスク、ブランチ名、未 push コミット、未コミットの作業ツリー（いちばん新しい情報）から拾います。
4. **実態と照合する（核心）**: 「実装済み」とあっても `git log` で revert がないかを確認し、「未着手」とあっても `git status` や diff を見ます。現在有効な設定はコードや設定ファイルで確認します。検証するのは、これからの行動が依存する主張だけです。
5. **ブリーフィングを返して止まる**: 最後に「どれから進めるか」を聞いて止まります。

## 出力の形
1. プロジェクトの構図（何を作っているか、成功の測り方、意思決定の単位、確定済みの学び）
2. 直近の状態の表（`実装済み・測定前` / `revert 済` / `未コミット` / `未着手` など曖昧さのない言葉で）
3. 次の一手の候補（依存順・順序制約つき）
4. 作業ルール（指示ファイルや feedback 系 memory 由来の禁止事項・優先順位）
5. 不明点・矛盾（doc と実態のズレ）

各項目に出典パスを添え、長い本文の引用はしません。

## 注意点
- docs を頭から全部読みません。memory の記述を検証せずに事実として言い切りません。
- 「理解しました」やファイル名の羅列で終えません。
- 読み込みの流れで実装を始めません。古い memory / doc を見つけても、このスキルの中では書き換えずに指摘するだけにします。
- VCS がない環境では照合が弱くなることを出力で断ります。
- SKILL.md の末尾に、AB テストを回している Unity のゲームでの例（revert 済みの機能、未コミットのビルド番号変更などのズレ）が載っています。
