# context-handoff

セッションを終える・立ち上げ直す前に、プロジェクトの docs・assistant memory・VCS を「次のセッションが正しく再開できる状態」に更新し、引き継ぎを残すスキルです。

> このファイルは人間向けの説明です。Claude が実際に読むのは [SKILL.md](./SKILL.md)（英語）で、動作はそちらで決まります。

agent-harness を導入していないリポジトリ向けです。導入済み（`.harness/` と `docs/handoff.md` がある）なら `session-handoff` を使います。読み込み側の [context-catchup](../context-catchup/README.ja.md) と対になっていて、「次のセッションが catchup して検証してもズレが出ない状態」を目指します。

## こんなときに使う
- 「セッション立ち上げ直したいから docs とメモリを最新化して」
- 「引き継ぎを書いて/残して」「メモリを最新版にして」
- 「docs とメモリを確認して最新にして」「セッション終了の準備をして」
- 「/clear する前に状態を残して」、別マシンや別セッションに引き継ぐ前

数分後に続ける途中の作業や、単発の Q&A だけのセッションでは使いません。

## やること
1. **棚卸し**: `git log --oneline` と `git status --short` で、特に**未追跡の doc**がないかを見ます。memory ディレクトリは `ls -la` で mtime を見て、並行セッションによる更新の痕跡を探します。
2. **三層の整合チェック（核心）**: memory の「`MEMORY.md` の索引行」「各ファイルの `description`」「本文」は別々に古くなります。三層とも VCS や実物と突き合わせ、遅れている層を揃えます。迷ったら mtime と VCS で判断します。化石化した「as of <日付>」も探します。
3. **並行更新を尊重する**: 書き換える前に必ず読み直します。別のセッションのほうが新しく正しければ触りません。Write が「file modified since read」で弾かれたら警告として受け止め、そのままリトライはしません。
4. **未コミットの正史 doc を救出する**: プロジェクトのコミット制約（秘密情報・個人データ・固有の禁止事項・メッセージ規約）を確認してからコミットします。意図的に追跡していないものはそのままにし、報告で明記します。
5. **このセッションの事実を書き足す**: コードと git から導けないことだけを足します。決定と理由（採らなかった案とその理由も）、踏んだ罠と直し方、`NEXT: ...` の形の resume point と順序制約です。相対日付は絶対日付に直します。
6. **触らない判断も成果物にする**: 役目を終えた歴史的な doc は、現状の正がどこにあるか明確なら書き換えません。
7. **報告する**: 更新したもの / コミットしたもの / 確認したが触らなかったもの（理由つき）/ 次のセッションの再開地点 を伝えます。再開地点を言い切れないなら、どこかに漏れがあります。

## 注意点
- 三層のうち 1 層だけ直して満足しません。
- 読み直さずに memory を上書きしません（並行セッションの更新を潰してしまうため）。
- 歴史的な doc を全面的に書き直しません。git が記録済みのことを memory に複写しません。
- セッションの時系列の経緯や、コードを読めば分かる構造は書きません。
- SKILL.md の末尾に、Python + Unity のリアルタイム映像システムで複数セッションが並行していた実例が載っています。
