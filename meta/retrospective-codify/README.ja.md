# retrospective-codify

今のセッションで試行錯誤した内容を振り返り、再利用できる手順を新しいスキルとして書き出すメタスキルです。

> このファイルは人間向けの説明です。Claude が実際に読むのは [SKILL.md](./SKILL.md)（英語）で、動作はそちらで決まります。

## こんなときに使う
- 「このセッションをスキル化して」
- 「今やった手順を skill にして」
- 「codify what we did」「retrospective」

明示的に頼まれたときだけ動きます。作業が終わったからといって自動では発火しません。

## セッションから拾うもの
- 実際に解決した作業を、一回きりの出来事ではなく繰り返し起きる場面として捉えたもの
- うまくいった手順・コマンド・判断（順番どおり）
- 失敗と落とし穴: 最初に何を試し、**なぜダメだったか**。ここがいちばん価値のある部分です
- 決まりきった処理で、`scripts/` に切り出せそうなステップ

## やること
1. 候補（繰り返す作業、手順、落とし穴）を数行にまとめ、スキル化する価値があるかユーザーに確認します。
2. 置き先を決めます。`agent-skills` リポジトリ（共有・配布される）か、このセッションで扱ったプロジェクトだけのローカルスキルか。
3. [skill-creator](../skill-creator/SKILL.md) の 3 条件（問題を解決するか・再現性があるか・目新しさがあるか）で絞り込みます。一回きりや自明な内容ならそう伝えて止めます（memory で十分なことがあります）。
4. 下書きします。
   - `name`（kebab-case）と、次回ユーザーが実際に言いそうな発火語を入れた `description`
   - 本文は、うまくいった手順と「Gotchas / うまくいかなかったこと」の節
   - 決まりきった処理は `scripts/` に書いて本文から参照します
   - `agent-skills` 向けなら、書きながら汎用化します（プロジェクト固有の名前は「Worked example」節に分けます）
   - 置き先に関係なく、公開安全チェックをします（貼り付けた API キー、社内 URL、個人のパスなどを消します）
5. `agent-skills` なら `<category>/<name>/SKILL.md`、ローカルなら `<project>/.claude/skills/<name>/SKILL.md` に書きます。
6. `agent-skills` なら `.claude-plugin/marketplace.json` の plugin の `skills` に追加し、`claude plugin validate .` を実行します（`./install.sh` は Codex や plugin を入れていないマシン用）。`name` とディレクトリ名の一致、発火語が具体的かも確認します。
7. 新しいスキルはセッション開始時に読み込まれる（`/clear` か新しいセッションが必要）と伝えます。

## 注意点
- 何でも詰め込んだスキルより、焦点を絞った 1 つを優先します。無関係な 2 つの話題があれば、2 つに分けるかどちらにするか聞きます。
- セッションで実際に起きていない手順を作りません。確証のないものは「unverified」と書きます。
- SKILL.md の規約そのものは [skill-creator](../skill-creator/SKILL.md) に従います。
