# skill-creator

この `agent-skills` リポジトリに、規約どおりの新しい Claude Code スキルを対話しながら作るメタスキルです。既存スキルを規約に合わせて直すときにも使えます。

> このファイルは人間向けの説明です。Claude が実際に読むのは [SKILL.md](./SKILL.md)（英語）で、動作はそちらで決まります。

## こんなときに使う
- 「スキルを作りたい」「スキルを追加して」
- 「SKILL.md を書いて」「スキルの雛形がほしい」
- 「この作業手順をスキルにして」
- 既存のスキルをリポジトリの規約に揃えたいとき

## やること
1. **置き先を決める**: `agent-skills` リポジトリ（配布元なので実質公開）に入れるのか、特定プロジェクトの `.claude/skills/` だけに置くプロジェクトローカルなスキルなのか。文脈で分からなければ聞きます。
2. **要件を集める**: 名前（kebab-case）とカテゴリフォルダ、解決したい作業、発火させたい言い回し、本文に入れる手順・知識・禁止事項、同梱ファイルの要否。分からないところだけ聞きます。
3. **3 条件チェック**: 問題を解決するか、再現性があるか、目新しさがあるか（既存スキルや Claude の素の能力で足りないか）。怪しければ「スキルではなく memory で十分かも」と伝えます。
4. **生成**: `agent-skills` なら `<category>/<name>/SKILL.md`、プロジェクトローカルなら `<project>/.claude/skills/<name>/SKILL.md` を作り、必要なら同梱ファイルも置きます。
5. **使えるようにする**: `agent-skills` なら `.claude-plugin/marketplace.json` のカテゴリ plugin の `skills` に追加し、`claude plugin validate .` を実行します。Codex や plugin を入れていないマシンでは `./install.sh` で `~/.claude/skills/` にフラットにリンクします（同じ Claude プロファイルで両方使うと二重に読み込まれるので注意）。
6. **検証**: frontmatter の `name` がディレクトリ名と一致しているか、`description` に具体的な発火語があるか。`agent-skills` 向けなら汎用性チェックも、どちらの置き先でも公開安全チェックもします。
7. **案内**: スキルはセッション開始時に読み込まれるので、見えなければ `/clear` か新しいセッションで再起動するよう伝えます。

## SKILL.md の主な規約
- frontmatter は `name` と `description` が必須で、`compatibility` は任意です。
- `description` だけを見て発火が決まるので、ユーザーが言いそうな語や場面を積極的に詰め込みます。
- 本文で `ALWAYS` / `NEVER` を多用せず、「なぜ」を説明します。
- 段階的開示（progressive disclosure）: メタデータは最小限にし、本文はできれば 500 行以内、重い内容は `scripts/` `references/` `assets/` に分けます。
- 改善は「下書き → 実際に呼んでテスト → ユーザーレビュー → 改善」のサイクルで回します。育てたいスキルには `evals/evals.json` を置いて定量評価することもできます。

## 注意点
- **汎用性チェック（`agent-skills` 向けのみ）**: スクリプトは完全に引数・設定で動くようにします。特定プロジェクトの具体例は「Worked example」と見出しを付けた節に 1 つだけ置き、一般ルールに混ぜません。抽象化するときに「なぜそうなるか」を落とさないようにします。プロジェクトローカルなスキルではこのチェックは不要です。
- **公開安全チェック（常に）**: API キーなどの秘密情報、`/Users/<実名>/...` のような個人を特定できるパスやユーザー名、社内 URL、顧客名を書き込まないようにします。環境依存の要件は `compatibility` に明記します。
- 避けたい形: 発火語のない description、一般論だけの本文、無関係な機能の詰め合わせ。
